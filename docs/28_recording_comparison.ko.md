# 이전 기록과 현재 기록 비교하기

0.4.0부터 대시보드의 **Compare recordings**에서 보관된 시간·상태를 비교합니다.
예전 Reqover JSON을 불러오면 API별 관측 건수, 평균·p95 처리 구간과 HTTP 오류 비율이
현재 기록에서 얼마나 달라졌는지 보여줍니다. 통제된 부하 테스트나 자동 합격 판정은 아닙니다.

![실제 예제 요청 5건의 관측값과 합성 시간 기준선을 비교한 라이트모드 화면](assets/reqover-recording-comparison.png)

2026년 10월 7일 라이트모드로 촬영했습니다. 현재 기록은 v0.4.2 MVC 예제에 실제 요청
5건을 보낸 관측값입니다. baseline은 기능 검사를 위해 그 관측 시간에 2를 곱한
합성 데이터이며, 파일 이름도 `synthetic-baseline.json`으로 표시합니다. 두 번째 실제
실행이나 성능 개선을 증명하는 벤치마크가 아닙니다. [촬영 기록](32_current_screenshot_capture.ko.md)을 참고합니다.

## 사용하는 흐름

1. 이전에 기록한 coverage report JSON을 준비합니다.
2. `Compare recordings`에서 `Import baseline JSON`으로 불러옵니다.
3. 평균·p95·HTTP 4xx/5xx 비율의 변화를 보고 검색과 정렬로 확인할 API를 좁힙니다.
4. 시험 환경·시나리오·수집 범위를 직접 확인합니다. 체크했더라도 자동 판정은 하지 않습니다.
5. `Export current summary`로 현재 집계를 남겨 다음 비교의 기준으로 사용합니다.

파일은 브라우저 안에서만 읽습니다. 외부 서버와 localStorage에 저장하지 않고,
잘못된 파일을 불러오면 이전에 성공한 비교 결과를 보존합니다. 입력 한도는 10 MiB와
원본 관측 50,000개입니다. 초기화 버튼은 baseline과 조건 확인을 해제합니다.

`omittedRequestDetails`가 있으면 상세가 잘린 원본 JSON이므로 전체 비교에 사용하지
않습니다. live 리포트에서 내보낸 집계 요약을 불러옵니다. 동일 기록의 부동소수점
계산 잡음은 작은 epsilon 안에서 0으로 처리하고 실제 작은 시간 차이는 유지합니다.

## 숫자를 볼 때 주의할 것

현재 통계는 그래프에 보이는 최근 100개가 아니라 **보관된 HTTP 요청 전체**를 사용합니다.
원본 JSON의 시간은 나노초 차이를 계산해 1 ms 미만의 값을 0으로 뭉개지 않습니다.
완료되지 않았거나 역행한 시간은 미측정이고, HTTP 상태가 없으면 성공으로 계산하지 않습니다.

시간 변화는 `현재 - 이전` ms입니다. 오류 변화는 각각의 알려진 상태를 분모로 한
비율의 **퍼센트포인트 차이**입니다. 예를 들어 50%에서 25%가 되면 -25 pp입니다.
예상한 400 응답도 테스트 성공일 수 있으므로, HTTP 오류 비율을 테스트 실패율로 읽지 않습니다.

- 평균이 짧아져도 입력·환경·분기·보관된 표본이 달랐을 수 있습니다.
- 관측·시간 표본수가 다르거나 상태가 빠졌다면 경고를 함께 봅니다.
- 시간 표본 20개 미만의 표시는 주의 안내일 뿐, 20개 이상이면 충분하다는 보장은 아닙니다.
- 한쪽에만 보이는 API는 그때 실행을 관측하지 못했을 수 있습니다. 생성·삭제로 단정하지 않습니다.
- 예전 파일에 시간 정보가 없으면 비교 불가이지, 이전 시간이 0이라는 뜻이 아닙니다.
- 측정 구간은 서버 어댑터의 벽시계입니다. 클라이언트 응답시간·TPS·CPU 사용량과 다릅니다.

## 내보내는 파일

요약은 `reqover-recorded-summary`라는 별도 종류의 JSON입니다. 생성 시각과 API별
관측·상태·시간 집계만 담고 요청 ID, 메서드 목록, 인증정보나 본문은 담지 않습니다.
다만 endpoint 이름은 민감할 수 있으므로 파일을 자동으로 공개하지 않습니다.
CLI의 coverage JSON이나 테스트 초안 JSON과는 서로 다른 형식입니다.

기존 agent·수집 동작·coverage JSON·CLI는 그대로 유지합니다. 아직 없는 실제 부하 run,
시험 결과 자동 수집, 메서드 시간·DB 원인 분석이나 성능 회귀 합격 판정을 추가했다고
주장하지 않습니다. 검증과 재현 명령은 [영문 안내](28_recording_comparison.md)에 있습니다.
