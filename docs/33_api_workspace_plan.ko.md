# API 그룹 대시보드 개발 계획

2026-10-12. 승인된 멘토링 방향의 첫 구현 단계. 제출 명세서와 기존 API/CLI 계약은 유지한다.

## 범위

- 독립적인 API workspace를 추가한다. 기존 Request map, Retest map, 코드 후보와 테스트 편집기를 유지한다.
- 전체 보관 HTTP 집계에서 경로 첫 구간별 그룹을 만든다. 서비스 클러스터 또는 호출 관계로 오해하지 않도록 명시한다.
- 그룹과 API 목록을 전환한다. API 검색, 호출 수/시간/HTTP 상태 필터, 열 정렬, 페이지 이동과 선택을 지원한다.
- 필터 후 상위 20개 선택, 선택 해제, 선택 건수와 관측 요청 비중 표시, 대표 요청 기반 JSON 초안 묶음 내보내기.
- 그룹 평균은 유효 시간 합계/표본 수로 계산한다. API별 p95를 평균 내지 않고 그룹 p95는 표시하지 않는다.
- 통계는 전체 보관 집계, 대표 요청은 최근 100개 상세다. 대표 상세 없는 API도 선택 가능하지만 초안 누락 목록으로 명시한다.
- ReqOver는 대시보드 표시 이름만 변경한다. 패키지와 Maven 좌표는 변경하지 않는다.

## 순서와 검증

1. 순수 데이터 모델 테스트를 먼저 실패시킨다: 그룹 합계, 가중 평균, 미측정, 검색/필터/정렬, 대표 상세 선택.
2. 기존 집계 JSON을 재사용하는 모델/뷰/CSS를 별도 파일로 추가하고 HTML renderer에 연결한다.
3. 작은 실제 예제와 120개 API 합성 fixture로 그룹/페이지/선택/내보내기/안전한 문자열/모바일/다크모드 확인.
4. 기존 Java report 테스트와 대시보드 회귀 검증, 새 Node 모델 테스트를 실행한다.
5. 한영 README 안내, 기능 문서와 트러블슈팅 기록을 갱신하고 PR 제출. 민감 자료는 공개하지 않는다.

## 후속 단계

시간별 히트맵, 5분 구간 집계, 시나리오 import/Postman export는 별도 구현한다.
현재 전체 보관 집계에는 시간별 구간 정보가 없으므로 최근 100개로 전체 트래픽 히트맵을 꾸미지 않는다.
자동 실행/실행 결과 수집/부하 생성/서킷 브레이커는 이 단계의 기능이 아니다.
초안은 검토 전 상태로만 내보내며 본문, 인증, 원래 파라미터 또는 기대 결과를 만들어 넣지 않는다.
