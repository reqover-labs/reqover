# 대시보드 사용성 보완 기록

2026-10-12, PR #53 후속 보완. 기존 CLI·수집기·coverage JSON 계약은 그대로다.
이 기록은 실제로 새 브라우저 클릭 검증을 완료했다고 주장하지 않는다.

## 코드와 단위 테스트로 확인한 문제

| 문제 | 수정 |
| --- | --- |
| 그룹 제한을 목록 하단에서만 알 수 있음 | 필터 바로 아래 그룹 이름·Clear group 표시 |
| 검색·숫자·상태 조건을 일일이 되돌려야 함 | Reset filters 추가. 선택과 정렬·그룹 깊이는 유지 |
| Groups로 전환하면 선택 상태·명령이 숨음 | 선택이 있으면 그룹 화면에서도 선택 요약과 명령 표시 |
| 선택 수와 생성 가능한 초안 수가 다름 | 작업 전에 사용 가능한 출처 수·최근 상세 없는 수 표시 |
| 같은 출처로 반복 생성하면 중복 초안이 생김 | API·요청 ID·시작 시각 기준으로 기존 초안 재사용. 편집 내용 유지 |
| 묶음 생성마다 편집기를 여러 번 다시 그림 | createMany로 한 번에 추가하고 마지막 항목 한 번만 표시 |
| API 이름 클릭이 부분 검색임 | 정확한 endpoint 선택. 직접 입력 검색과 Esc는 기존 동작 유지 |
| 메뉴 전환 후 이전 화면의 스크롤이 남음 | 다른 섹션으로 이동할 때 맨 위로 이동 |
| 이미 선택한 보기 버튼을 눌러도 페이지가 초기화됨 | 같은 보기는 유지하고 그룹·표 페이지를 별도 기억 |
| 긴 API 표에서 열 이름을 잃음 | 표 영역 높이 제한·고정 열 머리글. 인쇄는 높이 제한 해제 |
| Request map 비활성 이유가 불명확함 | 개별 HTTP 상세가 없다는 tooltip 추가 |
| API workspace에서 `/`가 숨은 기존 검색란을 선택함 | 현재 보이는 검색란만 선택, 검색란 없는 화면에서는 무시 |

## 확인 범위와 남은 검증

- selectionSummary 모델: 숨은 선택·관측 수·대표 상세 누락을 검증.
- addUnique 모델: 같은 요청 반복 입력, 편집된 초안 보존, 입력 배열 불변을 검증.
- 필터 controller: 브라우저가 아닌 최소 DOM 대역 단위 테스트로 `/orders/1`,
  `/orders/10`, 대소문자 다른 경로의 정확한 선택과 수동 검색·Esc를 검증.
- Java renderer/CLI 테스트와 JS 문법 검사를 실행한다.
- 이전 단계의 브라우저 검증과 이번 검증을 구분한다. 이번 수정 뒤 브라우저 E2E,
  모바일/다크모드 배치, 스크린샷 재촬영은 아직 수행하지 못했다.
- `scripts/verify-api-workspace.cjs`에 필터 초기화·선택 유지·반복 초안 생성·편집 보존
  검증을 추가했다. 실행 가능한 환경에서 이 새 브라우저 검증을 수행해야 한다.

기존 기능 문서의 이미지는 첫 구현 단계이며 현재 추가된 초기화·출처 안내 컨트롤은
포함하지 않는다. 새 이미지를 촬영하기 전까지 이 점을 명시한다.
