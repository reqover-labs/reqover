# 규모별 보기 연결 (미출시)

## 전체 → 그룹 → 요청

- **Distribution:** 5분 UTC 구간 × 어댑터 처리 시간 히트맵. 셀은 보관 건수이며
  색 농도는 가장 많은 셀 대비 로그 척도다. 빨간 테두리는 5xx, 주황은 4xx다.
  테스트 실패나 서킷 브레이커 상태를 나타내지 않는다.
- **Groups / API list:** 열 제목을 누르면 그 시간의 모든 처리 구간, 셀을 누르면
  해당 시간·처리 시간대만 선택한다. 그 범위의 정확한 API 통계를 그룹·목록으로 넘긴다.
- **Request map:** API 행의 버튼으로 같은 범위에 남은 최신 요청을 기존 관계도에서
  연다. 코드 집합과 관측 관계이지 호출 순서나 메서드 span은 아니다.

API workspace는 API가 50개 이상이거나 보관 HTTP 관측이 1000건 이상이면
Distribution, 나머지는 Groups로 시작한다.
소수 요청은 기존 Overview의 Request map을 사용할 수 있으며 보기 전환은 항상 가능하다.
50개는 UI 기본 선택 기준일 뿐 처리 용량 제한이 아니다.

시간 범위를 새로 고르면 이전 API 선택과 검색·상태·건수·p95 조건을 지운다.
정렬과 그룹 깊이는 유지한다. All recorded time은 시간·지연 범위를 해제하고 전체
보관 통계로 돌아간다. 일반 Reset filters는 시간 범위를 유지한다.
현재 범위와 해당 범위의 통계를 화면 위쪽에 표시한다.

## 집계와 한계

**최근 100개 상세로 히트맵을 만드는 게 아니라, 그 제한 전의 보관 HTTP 전체를
Java에서 집계한다.** 각 구간·시간대의 평균과 p95는 실제 표본으로 계산한다.
API별 백분위수를 합치거나 평균 내지 않는다. 처리 시간대는 0~100 ms 미만,
100~500 미만, 500~1000 미만, 1000~2000 미만, 2000 이상과 미측정이다.
미완료·음수 시간은 미측정이고, 0 및 1 ms 미만은 유효하다.

최근 비어 있지 않은 구간 256개까지 표시하며 생략 요청 수와 브라우저 Date 범위
밖의 시각 수를 알린다. 비어 있는 시간 구간은 압축된 Gap 표시로 구분한다.
빈 셀은 보관된 관측이 없다는 뜻이지 실제 트래픽이 없거나 정상이라는 증거가 아니다.
삭제된 관측은 복원하지 못하고, 이미 상세가 잘린 JSON은 그 파일에 남은 범위만 집계한다.

초안 출처는 여전히 최근 HTTP 상세 100개이며 선택한 시간·지연 범위와 일치해야 한다.
과거 구간의 집계는 있어도 상세가 없으면 생성 버튼을 비활성화하고 누락 수를 알린다.
묶음 내보내기에 선택 시간·처리 시간대를 `scope`로 남긴다. 원래 입력이나 인증정보·
기대 결과는 만들지 않는다. 영구 히스토리·자동 재실행·부하 생성·운영 요청 차단은 없다.

HTML 내부 `reqover-time-data`는 별도 schema 1 집계이며 기존 coverage JSON·CLI
입력을 바꾸지 않는다. 시각화용 JSON은 내부 API 이름을 담을 수 있어 자동 공개하지 않는다.

## 검증 상황

Java: 100개 제한보다 많은 150건, 시간 경계, 상태 수, 비HTTP 제외, UTC 정렬,
256개 구간 제한과 극단 시각을 검증한다. Node 모델: 반열린 시간 범위, 시간대별
출처 제한과 Gap을 검증한다. 실제 브라우저가 아닌 DOM 대역 controller 테스트로
전체 → 그룹 → API → 요청 이동과 범위 밖의 최근 요청을 사용하지 않는 것을 확인한다.

**실제 브라우저 시각 검증·E2E·모바일/다크 배치·이미지 재촬영은 아직 미완료다.**
controller 대역 테스트는 브라우저 검증을 대체하지 않는다. 검증 스크립트에는 히트맵
합계·범위 선택 검사를 추가했고, 기존 문서 이미지는 앞선 구현 단계임을 유지한다.
