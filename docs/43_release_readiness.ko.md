# 다음 버전 출시 준비와 대회 피드백

2026-10-23. PR #53의 다음 버전 후보는 0.5.0이다. 아직 버전·태그·배포물은 변경하지 않았다.

## 앞서 정한 1~4번의 상태

| 작업 | 현재 상태 | 남은 것 |
| --- | --- | --- |
| 1. 기능검증 결과 정리 | 내부 사전 검사와 사용자 피드백 정리 | 실제 대회 기능검증 결과는 미수신 |
| 2. 새 화면 직접 확인 | 합성 기록 8개 흐름의 실제 브라우저·좁은 창·라이트/다크·키보드·다운로드 검수, 작업 메시지 오류 수정 | 실제 모바일 기기·다른 브라우저·확대/접근성 추가 조합 |
| 3. PR 머지와 버전 정리 | 기존 PR 업데이트, 출시 문구·순서 준비 | 실제 화면 확인 후 머지, 버전 변경·새 빌드·스크린샷·릴리스 |
| 4. CI 시나리오 재실행 | 새 composite Action·워크플로·Job Summary·결과 artifact·옵션 비교 구현 | 실제 GitHub 실행 결과를 아래 증거 문서에 기록 |

대시보드 접근이 도구에서 차단된 상태를 다른 URL·브라우저·간접 실행으로 우회하지 않는다.
실제 화면 확인과 대회 판정이 없는 상태를 완료로 바꾸지 않는다.
이전 [화면 검증 인계](45_browser_validation_handoff.ko.md) 후 사용자가 재시도 금지를 해제했다.
직접 접속이 성공해 [실제 브라우저 검수](46_rendered_browser_review.ko.md)를 진행했다.
합성 fixture·viewport 검수 범위와 실제 모바일 기기 등 미수행 범위를 구분하며, 대회 판정은 여전히 미수신이다.

## 받은 피드백과 처리

| 출처 | 내용 | 처리 |
| --- | --- | --- |
| 사용자 | standard에서 Error 등 기능이 안 보임 | v0.4.2의 Requests → All → HTTP 4xx / 5xx라는 실제 이름으로 연습 가이드 수정. 화면 미표시 원인은 미확정 |
| 사용자 | 사이드 스크롤 스타일 개선 | 얇은 테마 스크롤바, 선택 메뉴 표시, 짧은 창에서 사이드바 내부 스크롤·모바일 메뉴 유지 |
| 앞선 멘토링 | API가 많을 때 보기 어려움 | Groups/API list/Distribution·시간 구간 선택·선택 API 초안 흐름 구현 |
| 앞선 멘토링 | 재테스트와 이력 연결 | 시나리오 파일·로컬 실행·실행/관측 이력·이번 CI Action으로 연결 |

새 대회 피드백을 받으면 항목 번호·환경·입력·기대 결과·실제 결과·재현 여부·수정 커밋·재검증을 적는다.
현재 파일에 임의의 심사위원 평가나 점수를 만들지 않는다.

## 머지 직전 확인

1. 작은/중간/큰 기록에서 Overview → API workspace → 초안 → 시나리오 → 실행/관측 이력을 직접 사용한다.
2. 390px와 낮은 데스크톱 창에서 사이드바 마지막 메뉴, 가로 표·초점·스크롤을 확인한다.
3. 파일 import 실패·선택 해제·검색·자기 비교 방지·실제 다운로드를 확인한다.
4. 최신 head의 Java 17/21·리포트/impact·OSV·saved scenario checks가 통과했는지 확인한다.
5. 대회 제출 버전과 새 릴리스를 구분한 뒤 PR을 머지한다.

## 릴리스 설명 초안

Reqover 0.5.0은 관측 요청에서 재테스트 대상을 선택하고 검토한 시나리오를 반복 검사하는 흐름을 확장합니다.
API 그룹·처리시간 분포·시간 구간 선택에서 요청 관계도로 이동하고, 선택한 API로 테스트 초안을 만듭니다.
시나리오 저장·Postman/JMeter 내보내기·로컬 실행·실행/관측 이력 비교를 제공합니다.
GitHub Actions에서는 저장 시나리오를 disposable 앱에 실행하고 상태·시간 조건과 결과 파일을 확인합니다.

현재 실행 범위는 명시적으로 허용한 로컬 GET/HEAD 순차 검사입니다. 원본 입력 재현·인증·원격 QA·
동시 부하·메서드/DB span은 제공하지 않습니다. 자동 검사 근거와 실제 브라우저 검증 결과를 구분해 공개합니다.
