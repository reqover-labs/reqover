## Reproduced defect and cause

Import malformed JSON in Scenario, then switch to Run history: the Scenario
`Import failed: ...` message remained visible. Removing a loaded run and switching
to Recordings also retained the run-removal message, sometimes alongside the
recording panel's own feedback.

All three subviews share `scenario-message`, but view switching did not clear it.
This was a feedback-lifetime problem rather than a collector, parser or execution
failure. Existing [selection/comparison fixes](41_workspace_followup.md) and
[troubleshooting](25_diagnostics_troubleshooting.md) guided the narrow scope.

- Clear only shared action feedback when changing subviews.
- Reselecting the active view retains its actionable error. Drafts, inputs, loaded
  histories and Current/Baseline selections remain intact.
- Added the regression first and observed `Scenario import errors must not appear
  in run history` fail. The same check passed after the fix.
- Rebuilt the CLI, regenerated HTML and reloaded the browser. Malformed import→same
  Scenario retained the error; switching to Run history cleared it. Run removal→
  Recordings cleared the unrelated removal message as well.
- Before/after screenshots are local task outputs. Personal recordings, raw logs
  and downloaded verification files are not committed.
