# 파일 선택과 대시보드 컨트롤 디자인 통일

2026-10-23 (KST). PR #53, 시작 commit `0455553`. fetch 후 원격과 일치했고 사용자 변경은 없었다.
배포된 0.4.2가 아닌 현재 소스의 화면 개선이다. [앞선 실제 검수](46_rendered_browser_review.ko.md)의
기능·이력·검토 상태를 유지하면서 파일 선택과 폼·버튼 배치를 정리했다.

## 관찰과 디자인 결정

| 관찰 | 적용한 기준 |
| --- | --- |
| Import scenario 버튼 안에 OS 기본 파일 선택 UI가 한 번 더 표시되고 높이가 다름 | 네 파일 불러오기를 같은 업로드 아이콘·44px 버튼으로 표현 |
| 입력·선택·액션의 높이, 모서리, 글자 크기가 화면마다 다름 | 공통 CSS에서 기본 44px·8px 모서리·13px 컨트롤 글자, compact 액션 36px 정의 |
| 저장·불러오기·재검토·다른 도구 내보내기가 한 줄에 섞임 | 시나리오 정보/저장 패널과 검토 후 내보내기 패널을 분리 |
| 실행 이력 검색란과 파일 버튼 기준선이 어긋남 | 액션 높이를 맞추고 데스크톱 검색은 오른쪽, 좁은 화면은 전체 폭으로 배치 |
| SVG 크기 규칙이 일부 아이콘에 적용되지 않음 | 줄바꿈 SVG에도 공통 18px 클래스와 장식용 aria-hidden 적용 |

기존 초록 포인트와 라이트/다크 팔레트를 유지했다. 저장·초안 생성·JUnit 다운로드를
주행동으로, 일반 내보내기를 보조 행동으로 구분하고 제거는 위험 색을 사용한다.
가까운 정보/행동을 패널로 묶고, 동일한 초점·hover·비활성 표현을 사용한다.
모바일에서는 필드와 시나리오 액션을 한 열로 배치하며 내용 높이를 고정해 자르지 않는다.

## 구현 순서와 범위

1. 수정 전 실제 화면과 renderer/CSS, 기존 트러블슈팅·선택 보존 계약을 확인.
2. 네 파일 입력의 ID·JSON accept·명시적 이름·다중 선택을 검사하는 회귀를 먼저 추가해 실패 확인.
3. `DiagnosticDashboard.filePicker`로 페이지의 파일 선택 UI를 공통화하고 `controls.css`를 컴포넌트 CSS 뒤에 포함.
4. 시나리오 패널과 액션 위계를 정리하고 나머지 주요 폼에도 같은 컨트롤 규격 적용.
5. 아이콘 문제를 별도 실패 검사로 재현한 뒤 원인 수정.
6. source CLI 빌드·전체 report/CLI 및 Node 검사·HTML 재생성·실제 브라우저 재검수.

파일 선택창 자체는 OS의 기본 동작이다. 페이지에서는 기존 native file input을
레이블 전체에 겹쳐 두고 기본 표시만 투명하게 한다. input을 제거하거나 Tab 순서에서
빼지 않으며 label의 focus-within으로 초점을 표시한다. 새 업로드 서비스나 의존성은 없다.

| 기존 입력 ID | 이름 | 다중 선택 |
| --- | --- | --- |
| `scenario-import` | Import scenario | 아니오 |
| `scenario-runs-import` | Import runs / history | 예 |
| `recording-import` | Import recording / catalog | 예 |
| `reqover-baseline-file` | Import baseline JSON | 아니오 |

모델·controller·검증 규칙·파일 schema·실행기·수집기·CLI 명령은 변경하지 않았다.
기존 선택 유지와 [작업 메시지 수명 수정](46_rendered_browser_review.ko.md)도 유지한다.
앞으로 컨트롤 규격을 바꿀 때는 마지막에 포함되는 `controls.css`를 기준으로 수정한다.
히트맵 셀·관계도 노드·표 정렬 버튼 등 데이터 표현 자체를 일반 폼 버튼으로 바꾸지는 않는다.

## 트러블슈팅: 줄바꿈 SVG와 눌린 아이콘

기존 `icon()`은 `<svg `라는 문자열만 치환했지만 실제 에셋은 `<svg` 뒤에 줄바꿈이 있었다.
따라서 `.ui-icon`과 `aria-hidden`이 붙지 않아 기본 24px 크기가 남았다.
새 컨트롤 검수 중 기준선 해제 버튼이 32px 폭이고 아이콘은 2px로 눌린 것을 실제 측정했다.

SVG 시작 뒤 공백 문자를 처리하도록 바꾸고, compact 아이콘 버튼은 36px,
기준선 해제는 일반 컨트롤과 같은 44px 정사각형으로 지정했다.
재빌드·reload 뒤 버튼 44×44px, 아이콘 18px, `aria-hidden=true`를 실제 DOM에서 확인했다.
업로드·다운로드·해제·네트워크 아이콘 회귀는 수정 전 실패하고 수정 후 통과했다.

## 실제 화면·파일 조작 검수

- 내부 브라우저, 합성 HTML과 전용 loopback 서버로 검수했다. 접근 차단은 없었다.
- 네 파일 선택 UI를 직접 사용했다. 실행/관측 다중 import와 기준선 단일 import·비교가 동작했다.
  실행 이력 및 기준선은 Enter로 파일 선택창을 열었고 초점 테두리를 확인했다.
- 시나리오 import→재검토→저장을 확인했다. 새로 불러온 사례는 여전히 검토가 필요하며,
  검토 전에는 실행용 내보내기가 비활성이고 검토 후 활성화됐다.
- 320×568, 390×844, 1024×480, 1440×900에서 히트맵/API 목록의 문서 가로 넘침이 없었다.
  모바일 폼은 한 열·전체 폭 액션으로 표시됐고 라이트/다크를 화면으로 확인했다.
- 화면 밖 파일 입력/체크박스를 바로 조작하려던 자동화는 한 번씩 대기/체크 오류가 났다.
  실제 화면 위치를 확인하고 정상 스크롤한 뒤 같은 컨트롤 조작이 성공했다.
  접근 차단이나 다른 주소로의 우회가 아니며, 이 도구가 자동 스크롤한다고 가정하지 않는다.
- 실제 다운로드한 HTML에 공통 컨트롤 CSS·네 파일 입력·아이콘 클래스·Lucide/Feather 고지가 포함됐다.
- 캡처된 브라우저 warning/error 로그는 빈 목록이었다. 화면 근거는 이 작업의 로컬 outputs에 보관했다.
