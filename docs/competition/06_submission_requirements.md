# 06. 제출 요구사항 정리

## 근거 문서

대회 공식 배포 문서 기준:

- 2026 오픈소스 개발자대회 운영규정 PDF
- 2026 오픈소스 개발자대회 결과보고서 양식 DOCX
- (해당 시 제출) 출품작 중복수혜 여부 확인서 DOCX

## 제출 파일

결과보고서는 총 2개 파일 제출이 필수입니다.

- HWP/HWPX 또는 DOC/DOCX 파일 1부
- 위 파일을 PDF로 변환한 파일 1부

결과보고서 작성 조건:

- 제출 기한: 2026-08-27 18:00
- 제출 방법: `osscontest.kr` 온라인 제출
- 글꼴: 맑은고딕, 본문 10pt
- 양식의 용지 여백 임의 변경 금지
- 결과보고서 본문 분량: 5페이지 이내
- 안내 페이지는 제출 시 삭제
- 회색 가이드 문구는 삭제하고 실제 내용은 검은색 텍스트로 작성

권장 파일명:

```text
2026 오픈소스 개발자대회 결과보고서_<접수번호>(<팀명>).docx
2026 오픈소스 개발자대회 결과보고서_<접수번호>(<팀명>).pdf
```

결과보고서에는 다음 항목이 들어갑니다.

- 팀명, 팀 인원, 참가부문, 과제유형
- 프로젝트명
- 프로젝트 공개 저장소 URL
- 시연영상 URL
- 프로젝트 소개
- 개발배경 및 목적
- 개발환경
- 시스템 구성 및 아키텍처
- 프로젝트 주요 기능
- 프로젝트 상세 내용
- 구동 및 시연
- 기대효과 및 활용분야
- 프로젝트의 혁신성 및 차별성
- 한계점 및 향후 발전 로드맵

## 붙임 1. SBOM

SBOM, 즉 소프트웨어 자재명세서는 필수입니다.

기재 항목:

- 번호
- 라이브러리명
- 버전
- 라이선스
- 공식 저장소 URL
- 사용 목적 및 주요 기능

Reqover에서 초기 SBOM에 들어갈 가능성이 높은 항목:

- Java
- Gradle
- ASM 또는 Byte Buddy
- Spring Boot
- Spring MVC
- Spring WebFlux
- Reactor
- Micrometer Context Propagation
- JaCoCo, 사용 시
- JUnit

주의:

- 모든 오픈소스 라이브러리, 프레임워크, 모델의 출처와 라이선스를 명확히 공개해야 합니다.
- JaCoCo를 단순 의존성으로 쓰는지, fork 또는 수정하는지에 따라 라이선스 정리 방식이 달라집니다.

## 붙임 2. AI 모델 활용 정보

AI 모델을 프로젝트에 탑재하거나 적용한 경우 작성해야 합니다.

Reqover 자체는 현재 AI 모델을 탑재하지 않는 개발자 도구이므로, 기본 전략은 다음과 같습니다.

- 프로젝트 기능에 AI 모델을 넣지 않습니다.
- 코드 작성과 디버깅 보조에 상용 AI를 사용했다면, 모델 탑재가 아니라 개발 보조 범위로만 정리합니다.
- 보고서에는 "프로젝트에 AI 모델은 탑재하지 않음"을 명확히 적습니다.

운영규정상 코드 작성 및 디버깅 보조용 상용 AI 서비스 활용은 허용됩니다. 다만 AI가 작성한 코드의 동작 원리에 대한 이해도가 부족하면 평가에서 감점될 수 있으므로, 핵심 구현은 설명 가능해야 합니다.

## 오픈소스 라이선스 요구사항

직접 작성한 소스코드는 OSI 인증 오픈소스SW 라이선스를 적용해야 합니다.

사용 가능한 대표 라이선스:

- MIT
- Apache License 2.0
- GPL-2.0
- GPL-3.0
- LGPL
- BSD

Reqover 권장 기본 라이선스:

- 자체 작성 모듈: Apache License 2.0
- JaCoCo fork 또는 수정 파일이 생길 경우: 해당 파일 또는 모듈은 EPL-2.0 요구사항 별도 검토

비상업적 조건이 붙은 라이선스는 원칙적으로 사용할 수 없습니다.

## 소스코드 공개 요구사항

출품작은 전체 소스코드를 포함해야 하며 심사 및 검증 가능한 상태여야 합니다.

요구사항:

- GitHub, Hugging Face 등 공개 저장소에 게시
- 수상팀은 수상일로부터 5년간 공개 상태 유지
- 임의로 private 전환 시 수상 취소 가능

Reqover는 GitHub 공개 저장소를 기준으로 준비합니다.

## 시연영상 요구사항

결과보고서 양식은 시연영상을 YouTube URL로 기재하도록 요구합니다. 별도 파일 제출은 불가합니다.

Reqover 시연영상 구성 권장:

1. 기존 전역 coverage의 한계 설명
2. MVC 동시 요청 분리 데모
3. endpoint별 coverage report 확인
4. WebFlux thread hop 귀속 유지 데모
5. 코드 변경 영향 범위 역조회

양식이 시연영상 칸에 요구하는 것은 "유튜브 업로드 후 URL 기재(별도 파일 제출 불가)"뿐입니다.
운영규정에도 영상의 공개 범위나 길이 제한 조항은 없습니다. 다만 두 조항에서 실질적 제약이
나옵니다.

- 제10조① 출품작은 "심사 및 검증이 가능한 상태"여야 합니다. 심사자가 열 수 없는 `비공개`는
  사실상 불가하고, `공개`와 `일부 공개`는 모두 가능합니다.
- 제12조② 수상·우수작으로 선정되면 시연영상이 대회 홍보와 정보집에 활용될 수 있고 참가자는
  이에 동의해야 합니다. `공개`가 이 조항과 마찰이 없습니다.

시연영상 URL은 접수 정보가 아니라 결과보고서 본문의 한 칸입니다. 제11조①에 따라 마감 기한
안에는 여러 번 제출할 수 있고 최종 접수분이 심사 대상이므로, 영상을 다시 올려 URL이 바뀌면
새 URL이 적힌 보고서를 다시 제출하면 됩니다.

## 중복수혜 확인

동일하거나 실질적으로 유사한 프로젝트로 중앙정부, 지방자치단체, 공공기관 예산이 투입된 타 지원사업에서 수혜를 받은 경우 신고해야 합니다.

중복수혜 판단에 포함될 수 있는 유형:

- 정부 지원 경진대회, 공모전, 해커톤 수상
- 정부 R&D, 산학협력 프로젝트 연구비 또는 개발비
- 정부 지원 교육/인재양성 프로그램의 프로젝트 개발 지원금

제외 가능성이 있는 유형:

- 민간 기업 주최 사업
- 대학 자체 예산 사업
- 프로젝트와 무관한 실비 또는 참여 수당

해당 이력이 있으면 확인서에 기재하고, 없으면 해당 없음으로 정리합니다.
